# 本地随记

Flutter + NobodyWho 6 的本地 AI 助理基础版本，支持 Android / iOS。

## 已实现

- 文字对话、图片理解、录音转文字；转写可编辑后发送。
- 统一模型库，每个功能按能力分配模型；一个模型可同时用于多个功能。模型配置和聊天记录使用 sqflite / SQLite 持久化。
- 用户主动通过 HTTPS 文件直链下载，或导入下载好的手机文件；不内置模型，不在发送消息时自动下载模型。
- 图片与录音复制到应用目录，分类收藏对话内容。
- 每次发送后用本地模型生成待确认内容；支持日期、提醒、电话、事项、记账及带自定义字段的分类笔记。用户在对话中同意或点击确认后才正式保存。
- flutter_local_notifications 单次本地提醒：补充/修改时间、取消、失败重试、重启恢复。
- 下载临时文件、失败清理、GGUF 文件头检查与 ZIP 路径检查。

## 使用

运行 `flutter pub get`、`flutter run`，在右上角进入模型中心。

1. GGUF：导入兼容 NobodyWho / llama.cpp 的模型，按模型说明勾选图片、音频能力；需要时再选择配套 mmproj。下载主模型时仍需从文件选择器导入投影文件。
2. 功能分配：文字、图片、语音分别从统一模型库选择。可共用一个支持这些能力的模型，也可使用不同模型。支持音频输入的多模态模型通过 AudioPart 转写；Whisper 通过专用 STT 接口转写。
3. 语音：导入默认精度的完整 Whisper ONNX 仓库 ZIP，保持 config.json、tokenizer 等配置和 onnx 子目录原始结构。ZIP 中只允许一套完整模型；也支持 SenseVoice int8（model.int8.onnx + tokens.txt）和 Qwen3-ASR sherpa-onnx 导出目录，不是 whisper.cpp 的 GGML/GGUF。
4. 可重复导入模型，通过功能分配下拉框切换；下一次推理使用新选择。推理期间锁定模型设置。

下载仅支持无需鉴权的 HTTPS 直链，不支持 Hugging Face 页面链接。自定义链接下载暂无断点续传、取消和文件摘要校验；模型列表下载支持取消、文件大小和 SHA-256 校验，但不支持断点续传。请保持应用在前台，保证足够的磁盘与内存。GGUF 头检查不能证明架构或投影兼容，加载失败会显示错误。

Android 最低 API 31，包含 arm64-v8a / x86_64。录音使用麦克风权限。模型初始化延迟到第一次推理，每个进程只初始化一次。

## 范围与后续

自动整理针对每条用户消息（包括录音转写后发送的文字），不把助理回复作为事实入库；纯图片中的信息目前不会自动作为结构化事实保存。整理默认复用对话模型，没有对话模型时使用已选择的图片模型，不需要额外下载专用模型。使用 NobodyWho JSON Schema 约束输出格式，再校验用户原文、号码、日期和金额；格式不合规会显示整理失败，可在该用户消息下重试。用户应核对模型结果，错误记录可删除。

支持五类专用记录及自定义分类笔记，SQLite schema 升至 v3，保留原有模型、聊天、手动收藏及正式记录。待确认内容保存在独立 record_proposals 表；提取完成标记与草稿原子提交，用户明确同意后才在事务中生成正式记录并调度提醒。拒绝不生成正式记录；重复确认不重复入账。删除后的记录不会因重试复活。失败提取不提交完成标记。应用恢复时还原待确认问题，并补做已确认记录的通知调度，不在启动时自动调用模型。

提醒时间使用用户原文的保守本地解析，支持今天/明天/后天、月日/年月日、本周/下周几、中文或数字时刻、几分钟/小时后。时间以发送消息时为基准，SQLite 存 UTC，展示为当前设备本地时间；已排定通知在跨时区后仍指向原来的绝对时刻。没有具体时刻、模糊表达、循环表达或不支持的时间格式会保持待补充；可在记录页选择日期和时刻，保存为单次提醒。已过去的提醒不补发，也不将“时间已过”伪装为“已送达”。待确认内容可在对话中补充或修改字段；已经正式保存的记录尚不支持通过后续对话修改或删除，请使用记录页操作。

通知使用 flutter_local_notifications + timezone + flutter_timezone，首次调度请求通知权限；拒绝会保存明确失败状态，开启系统权限后可重试。Android 已配置通知/精确闹钟声明、开机恢复接收器和 desugaring。未获精确闹钟特殊权限时使用非精确调度，并在记录中显示可能延迟；可点击记录页“允许精确定时”打开系统授权，授予后会重新调度有效提醒。iOS 最多接受本应用 60 个待提醒，超出后保留失败记录供重试；Android 强制停止或厂商省电可能阻止到达。点击通知目前打开应用默认首页，可切换到记录页查看。

金额使用整数分保存，按币种分别汇总，不用浮点数累加。金额、币种或收支方向缺失不参与汇总；当前只自动校验阿拉伯数字金额，中文大写金额等不确定金额保留待补充。JPY 当前沿用两位小数展示；尚未实现各币种最小单位差异。电话仅保存号码和标题，不写入通讯录或拨号。消息气泡不提供逐条手动存档按钮，记录通过对话或确认卡片同意后保存。音频可在记录卡片中播放、暂停和拖动进度。

后续可扩展：全文检索索引、循环提醒、下载续传、设备内存策略与模型释放。当前模型句柄依赖 SDK 的回收机制，每次请求创建实例，尚未进行真机内存压测。

本地数据为应用私有目录内的 SQLite 数据库和媒体文件（模型与聊天为 JSON 快照；结构化记录为独立行，含类型、来源、数据和提醒状态），未做应用层加密。切换模型后自动提供有长度预算的近期对话及相关本地信息摘要，并开放只读分页/详情工具查询全部正式记录、历史对话、收藏和草稿。草稿与正式记录明确区分。历史图片与音频只提供引用和已有文字，不会自动重新识别原文件。卸载应用通常会删除这些文件。

## 插件选型

Dio：模型下载与进度；image_picker：图片选择；record：WAV 录音；file_picker：模型文件选择；sqflite：SQLite 数据持久化；path_provider：本地目录；archive：Whisper ZIP 解包；nobodywho：本地推理。flutter_local_notifications：通知；timezone / flutter_timezone：时区；synchronized：串行化提醒写入与取消。测试通过 sqflite_common_ffi 验证 SQLite 持久化。

### iOS 构建的 SQLite 下载错误

若日志包含 `Building assets for package:sqlite3 failed` 和 `libsqlite3.arm64.ios*.dylib` 下载失败，项目已通过 `pubspec.yaml` 中 `hooks.user_defines.sqlite3` 让 iOS 加载系统 `/usr/lib/libsqlite3.dylib`，无需额外从 GitHub 下载 SQLite。应用业务数据库仍由 sqflite 管理。NobodyWho 的 iOS 模拟器运行库仅含 arm64，Debug/Release xcconfig 已在 Generated.xcconfig 后排除 x86_64；Intel Mac 模拟器不支持该版本的 NobodyWho，可使用真机或 Apple Silicon 模拟器。

## 在对话里完成记录与查询

例如：“今天午饭花了20元” → 自动生成记账卡片并询问是否记录 → 回复“同意记录” → 正式保存并回显结果；“明天提醒我买药” → 对话追问具体时刻 → 回复“明天上午九点” → 信息完整后按原明确意图直接保存并调度。无需手动填表或打开记录页。按钮确认是等价的可选入口。

对话确认通过确定性的意图匹配处理，不由模型自行批准。支持“同意记录/好的/好帮我记下来”“不要记录”“确认第2批/确认第二批”“全部记录”等；含糊的“好的”等短确认仅在上一条助理消息明确为待确认记录问题时接受；切换话题后不会误批准旧草稿。存在多批草稿时不把含糊的“好的”套用到任意一批，需指定批次或明确全部。带条件的“可以，但金额改成20”不会被当作批准。补充多批时可说“修改第2批：明天上午九点”。必要字段缺失时继续追问，未确认和不完整的内容不会生成系统提醒。

笔记类型允许模型从原文中生成分类和 label/value 字段，例如健康记录的体重、运动距离，按字段回显；模型不需要也不能执行任意 SQL。既有五种专用类型保留日期/时区、号码、收支方向/币种/整数分等不同数据结构。

本地读取工具是 `read_local_page(scope, query, offset)` 和 `read_local_detail(scope, id, offset)`，scope 仅允许 records/history/notes/proposals。关键词为空可遍历全部数据；nextOffset 支持继续读取，详情切片可读取完整长内容，没有只允许访问“最近几条”的限制。自动摘要是关键词检索，不是完整数据；复杂问题应继续调用工具。实际 0.8B 模型测试发现其可能不调用工具，因此名称或编号明确的常用查询、修改、关联、删除优先由应用执行；复杂语义仍提供模型查询工具。所有操作限于应用内数据，不提供任意 SQL、文件读取或执行命令能力。

## 删除模型

模型中心 → 模型库中每个模型右侧的删除按钮。确认框展示模型名称和正在使用它的功能；确认后清除该模型注册及全部对应功能选择，删除该模型应用内目录（包括 GGUF、配套 mmproj 或 Whisper ONNX/配置文件）。其他模型、聊天、记录和导入前的原始文件保留。之后可从列表重新下载或从本地重新导入。

先持久化移除模型和清理任务，再删除文件。配置写入失败时恢复原模型及功能选择；文件清理失败时保留重试任务，下次启动继续处理。仅允许清理应用 models/<id> 内的普通目录，拒绝越界符号链接；若另一个模型配置仍引用同一目录则保留共享文件。下载或导入期间禁用删除操作。相关测试覆盖取消/确认、共享功能选择、旧版导入目录、外部文件保护、配置失败及清理重试。

### 国内模型与记录删除

下载列表支持按国内厂商及文字/图片/语音组合筛选，移除外国厂商推荐。此操作不删除用户已下载或手动导入的模型。MiMo 7B 及大参数 Qwen/DeepSeek 标记为高内存候选，MiMo 不启用 MTP。MiniCPM-V 35B MoE 的激活参数不能当作总权重大小，因此未沿用文档中的 3 GB 内存推断。

记录页每条正式记录提供“删除记录”，确认后删除数据库记录。提醒先取消对应系统通知，取消失败时保留记录并显示错误，允许重试。旧版手动收藏也支持删除，写入失败恢复内存内容；删除记录不删除聊天原文。测试覆盖保留/删除、通知取消、重新打开后的持久化以及原文保留。

聊天界面采用暖白与墨绿配色，使用顶部入口访问记录和模型中心，不再显示底部 Tab。模型返回的 `<think>` 内容默认折叠，可展开查看；支持流式输出和未闭合标签，正文单独显示，原始对话仍完整保存在本地。

Qwen 文字系列已从下载推荐移除 Qwen3 0.6B / 1.7B / 4B / 8B，替换为 Qwen3.5 0.8B / 2B / 4B / 9B 的 Q4_K_M 社区量化版，每项附带同一固定版本仓库的 F16 图片投影，可供文字和图片共用。4B / 9B 标记为高内存候选。Qwen3-VL 和 Qwen3-ASR 属于独立的视觉/语音系列，继续保留；已有用户模型配置不受推荐清单变更影响。Qwen3.5 文件元信息已核对，但尚未完成本项目真机推理验收。

聊天页错误在顶部悬浮通知显示，无自动消失时间，需点关闭；长错误可在通知内部滚动查看。对话模型名称和快速切换位于发送按钮左侧，只列出已下载且支持文字对话的模型，切换会保存到本地且不改变图片/语音的功能分配。点击空白处、输入区外或拖动对话列表会结束输入焦点并收起键盘，保留未发送草稿。

发送消息时不再显示横向等待进度条；消息气泡移除用户/助理名称，直接展示对话正文、附件和必要的记录确认交互。

普通对话使用 NobodyWho `Chat.complete` 传递 system / user / assistant 独立角色，当前输入始终是末尾用户消息。历史正文按预算裁剪，过滤未完成、失败与空回复；助理 `<think>` 内容保留原始存储及折叠展示，但不自动回灌到近期历史或检索摘要。普通对话关闭模板思考模式；只有本轮有图片时才加载视觉投影。保留只读历史/记录查询工具与原有记录确认流程。使用实际 Qwen3.5 0.8B Q4_K_M 权重在 Mac CPU 和 Metal 上验证多问题及名字记忆，均能跟随问题回答；这不代表已复现或验收用户手机的全部情况。

模型存储与手机文件：模型、投影和媒体在持久化快照中保存为相对应用数据目录的路径，读取时根据当前沙盒解析。旧绝对路径若失效、但当前沙盒存在对应模型或媒体文件，启动时自动迁移。不会通过恢复逻辑删除或移动模型，也不改变有效的外部文件引用。模拟数据容器迁移已覆盖 GGUF、投影与图片，保留模型选择和对话。

下载确认框可选择“应用内（默认）”或“手机文件 + 应用内副本”。选择后者会先完整下载并校验模型，再弹出系统文件保存对话框，选择手机文件中的目标位置。为保证离线推理可继续访问，应用内保留一份副本。系统文件副本是包含主模型、投影/语音配置及相对路径清单的完整 ZIP 模型包。模型库每个条目右侧提供“导出到手机文件”，并可用“导入模型包 ZIP”重新导入；原有 GGUF 和语音 ZIP 导入仍保留。

导出使用 archive 文件流在后台 isolate 打包（存储模式），通过 flutter_file_dialog 的 sourceFilePath 打开系统保存面板，不将整个模型读入 Dart 内存。临时包在保存完成/取消/失败后清理，取消或导出失败不会删除已下载模型。需额外预留完整模型包与手机文件副本的空间。iOS 新文件插件已通过无签名构建，实际系统文件保存位置由用户在设备上选择。

模型调用审查：Qwen3.5 的非思考文字与图片使用各自采样配置（文字 temperature=1 / top_p=1 / top_k=20 / presence=2；图片 .7 / .8 / 20 / 1.5，最近 64 token 施加 presence penalty）；其他模型保留引擎默认采样。记录提取另用低随机度 .2 / .8 / 20，加 JSON schema 约束。参数依据 Qwen 官方模型卡，提取配置为本应用样本调试值，不是所有模型的通用推荐。

原长提取提示词在实际 0.8B 权重中对明确收支/电话/提醒返回空数组。现缩短指令，移除新记录提取中的旧历史摘要，加入角色明确且有原文依据的示例；JSON schema 属性顺序与示例一致，先输出电话/金额等专用字段，最后输出扩展 fields。未放松金额、号码、原文和时间校验。修改草稿先把 amountMinor 分转换为 amount 元字符串，把 at 转成 datetime 秒精度 ISO8601，修复金额单位/键名不一致和 UTC 时间双时区。初始化失败可重试；助理生成失败仍保留已发送用户消息供后续上下文使用。

审查后的实际 Qwen3.5 0.8B Q4_K_M + Mac Metal 样本已断言通过：带只读工具的算术和首都问答、问候无记录、20 元支出、13800138000 电话、明日上午九点提醒、支出修改为 25 元。少量样本不等于全场景或手机效果验收，记录仍必须经过用户同意。74 项自动测试通过。

助理默认姓名“随记”，身份为用户私人助理，性格开朗、礼貌、严谨、干练。支持在对话中修改姓名、性格、兴趣和说话风格，例如“以后你叫小白，性格改为温柔，喜欢音乐，说话简短一点”，回复更新结果并立即保存。复杂表达由当前本地模型提取，常用明确指令无需加载模型。支持“恢复默认人格”；人格独立于模型选择，重启后保留，不作为用户生活记录提取，历史人格修改消息不重复回灌。人格偏好不会放开记录确认和事实校验规则。

记录确认策略更新：用户明确说“帮我记一下”“记录今天…”或给出完整提醒指令时，该指令本身即是同意，提取结果完整且无不确定/否定/假设表述便直接保存、回显实际回执，不再追问是否记录。缺少时间/金额等则只追问缺失信息，明确请求的草稿补齐后直接保存；没有记录意图或存在歧义时仍保留确认流程。仅提醒指令不会一并批准同句的其他类型记录。明确记录请求先整理保存，不额外让聊天模型生成一轮重复确认。

关联已有记录：对“把车票关联到杭州旅行”这类明确关联请求，先用只读工具定位两条历史正式记录；查询唯一匹配或用户明确指定记录编号后，才允许 link_existing_records 更新两条原记录的 relatedRecordIds。关联双向去重，保留原记录 ID、source_id、金额、提醒状态等，不插入新记录。有多个候选或未查询时拒绝修改并让模型追问；此类请求不进入新增记录提取流程。记录页显示已关联对象的标题，聊天显示实际关联回执。

对话删除只在明确删除请求下开放 delete_existing_record 工具，必须先按用户描述查询并唯一定位单条正式记录。提醒经 RecordService 取消通知后才删除，失败保留记录；删除同时清理其他记录的关联引用。删除模式不展示模型自行声称成功的文字，只显示实际执行回执；未执行则明确显示“尚未删除”。已用会谎报“已清理所有记录”的测试模型验证不会误导用户。

记录 UI 使用内置白名单模板：birthday/date/reminder/expense/phone/task/note/image/audio，由模型在结构化输出中选择 template，body 为简短事实摘要；不执行模型生成的 UI 代码。生日优先提取原话中真实日期，以“1996年08月12日”展示；缺年份显示“每年08月12日”，农历不自动换算公历。支持中文数字日期；旧生日收藏也使用结构化卡片，来源原话折叠。图片可点开缩放，录音可播放/暂停、拖动进度，附件从原消息的本地媒体引用读取。编辑入口可改标题、模板、日期、电话号码、金额/币种/收支、备注和扩展字段值，保持原记录 ID 和关联；提醒时刻仍走调度服务，改提醒标题会刷新系统通知。

实际 Qwen3.5 0.8B 已验证完整生日、缺年份生日和支出模板输出，91 项测试和 iOS 无签名构建通过。音频播放和系统通知在真实手机上的交互仍需设备验收。

删除交互策略更新（覆盖前述直接删除说明）：delete_existing_record 只查找并创建持久化待删除请求，回显记录编号、字段摘要并询问，不操作数据库记录。用户下一轮回复“确认删除第N条”，或在当前待删除问题下回复“确认删除”/点击确认按钮，应用才调用删除服务；可回复“取消删除”或点保留。确认无需再次加载模型。没有实际回显、对象发生变化、确认对象不匹配时不删；提醒取消失败则保留记录并报告失败。待确认可跨重启保留，删除后清理关联引用，成功文案仅由应用执行回执生成。

已保存记录的修改工具 update_existing_record 先按用户描述唯一查询定位，再修改原 ID；支持标题、正文、电话、日期、金额、币种、收支、提醒时刻和展示模板。值需来自用户原话并经类型/日期/金额校验，不接受任意 SQL 或 ID 猜选；提醒时刻走通知取消与重新调度。查询工具始终可用；修改/删除工具仅在对应明确请求时提供，修改不进入新增提取流程。

输入区上方普通提示移到顶部悬浮 InfoNotice，4 秒自动关闭，也可手动关闭。更换提示内容重新计时，离开页面取消计时器；错误通知继续保留到手动关闭。录音转写提示也使用顶部通知。

补齐记录操作的实际执行链路：实际 Qwen3.5 0.8B 在工具调用测试中出现只口头响应、未实际执行，以及将 amountMinor=2000 错读为 2000 元。现在明确名称或编号的查询、字段修改、双向关联和删除预览优先由 RecordDialogue 查询数据库并调用既有受校验服务，无需模型正确调用工具，也无需配置模型；多个候选回显真实编号，等待用户指定。复杂请求仍可交给模型工具处理。修改和关联也只展示应用实际回执，不展示模型虚构完成的文字。模型侧记录资料改用主货币单位 amount 和 display，并标注 sourceQuote 仅为最初来源，后续修改以当前字段为准。

补查音频预览：切换记录释放旧播放器，异步加载中离开页面不再更新失效状态；失败后可重试加载，播放完成后按钮回到播放状态。系统播放效果仍以真机为准。100 项自动测试通过，另外实际 0.8B + 本地服务链路通过查询20元、修改25元、关联、删除预览/确认、人设姓名及生日模板断言。

追问交互：多个候选记录以可点击选项回显，保留待执行请求、候选顺序及编号，用户回复“第二条”或点击即可继续原来的修改/删除；关联支持连续选择两条。缺少目标时可直接补充名称，缺少修改值时可直接补充新值，不必重复整条指令。待交互状态保存到本地，只有最新对应问题接受简短续答，切换话题不会误套旧问题。支持“取消操作”。

记录草稿的“补充信息”和普通追问的“回复”按钮会聚焦输入框，保留现有文字；补充多批草稿时自动带批次前缀。删除问题下的“好的/确认/是的”只在当前待删除问题对应时作为确认，其他话题不触发。候选卡片及 1.8 倍字号已检查，107 项自动测试通过；iOS 无签名构建通过。

聊天中的实际付款、转账、借款、还款、收款事实，以及上传图片中识别到的账单、支付宝或微信支付记录，都会生成待确认记账。一张截图里的多笔交易逐笔整理；合计、余额、优惠和未支付订单不重复入账。识别不清的字段会等待补充，确认后才保存。

聊天上下文按应用实际 8192-token 窗口管理。发送前估算占用并预留回复、工具和图片空间，超过约 80% 时使用本地模型合并旧对话摘要，写入 app_state，重启后恢复。原始消息及识别原文不删除，仍可通过历史查询读取。发送按钮旁的圆环显示估算使用百分比，长按查看详情；压缩时显示加载状态。估算不是模型 tokenizer 的精确计数，图片成本也仅为预留估计。

GGUF 导入时自动读取 general.architecture 和对应的 <architecture>.context_length，保存 trainedContextLength；模型包导入、模型库安装和旧模型启动补识别使用同一读取器。该值为模型标称训练上下文，不代表手机可分配内存或当前聊天窗口。缺失、损坏或超出头部读取预算时显示未识别，当前聊天运行窗口仍为 8192 tokens。

模型加载、思考回复、图片识别、记录整理、语音转写和预热等等待过程使用聊天列表中的临时状态气泡，不写入历史或记录。当前任务进行期间可以编辑下一条文字及选图准备草稿，发送按钮在当前任务完成后恢复。

长按消息可选择“引用”，在输入区上方显示可取消的预览。发送后只保存 replyTo 消息关联，在新消息下方以单行文字、小图或音频标识回显；点击可跨历史分页定位原消息并高亮。引用原文进入本轮模型及记录提取上下文，引用本身不代表保存授权。音频在引用时不转写，处理请求发送后优先使用已有转写，没有时再识别一次并缓存。

模型通过 operate_app 统一调用 App 操作：查询能力及状态、打开记录或指定记录、设置和模型页、选择已安装模型、设置转写偏好、查询模型目录、后台下载与取消、导入导出文件流程、相册选图、清空正式记录和删除模型。工具只使用已注册ID及白名单参数；删除清空须在原生确认弹窗由用户确认，文件操作等待用户选择。页面打开和文件操作未完成不会回报为已保存/已下载。切换模型于下一次推理生效；新下载不覆盖已有用途选择。

后台推理：Android 使用可见 dataSync 前台服务和任务期间的 CPU 唤醒锁，任务结束即释放；Flutter 引擎缓存以允许 Activity 离开后继续处理。iOS 26+ 使用 BGContinuedProcessingTask，旧版使用 beginBackgroundTask 的有限延长时间；当前聊天使用 CPU，不伪造音频/GPU后台权限。系统到期后暂停后续解码，回到前台继续。系统或用户仍可终止进程；回复每两秒及离开前台时持久化，重启后保留半成品并标记中断，不自动重复执行工具操作。后台权限、低内存、省电和平台限时都可能影响执行，不能保证无限后台运行。
